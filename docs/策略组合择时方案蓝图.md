# A股策略组合 + 市场状态择时 方案蓝图

> 目标(用户原话):找到一个在 A股稳定挣钱的策略组合,不管牛熊,控制回撤,稳定盈利,提高盈亏比。根据策略组合筛选策略池,选出股票并提示买卖点。
>
> 验证标准(用户选定,强制):**严格 —— 任何进入"稳定策略池"的策略,必须通过 OOS + walk-forward。回测好看的数字不算数。**
>
> 本文档只做"蓝图与路线",不改任何代码。经你确认后再按阶段实施。

## 0. 一句话结论

单一策略在 A股无法穿越牛熊,这是市场结构决定的,不是调参能解决的。可行路径只有一条:**建一个经过严格验证的"策略池",再用一个"市场状态路由器"决定在什么行情下启用哪些策略、给多少仓位**。你现在的 `quant` 引擎已经具备做这件事所需的 90% 基础设施(优化/验证/进化/发现都已落地),真正缺的是两块拼图:(1) 把 `market_regime.py` 从"布尔过滤开关"升级成"多状态分类器 + 策略路由器";(2) 把 `user` 目录里的实战策略,经严格验证后正式"入池"。本文围绕这两块展开。

## 2. 目标架构:策略池 + 市场状态路由器 + 组合回测

```
                    ┌─────────────────────────────────────────┐
                    │  每日行情数据 (DuckDB daily_bar)          │
                    └───────────────┬───────────────────────────┘
                                    │
                    ┌───────────────▼───────────────┐
                    │  市场状态分类器 (RegimeClassifier)│  ← 改造 market_regime.py
                    │  输出: 牛市 / 震荡 / 熊市 (+强度)  │
                    └───────────────┬───────────────┘
                                    │  当日 regime 标签
                    ┌───────────────▼───────────────┐
                    │  策略路由器 (StrategyRouter)     │  ← 新增
                    │  regime → {启用哪些策略, 各自权重/仓位上限}│
                    └───────────────┬───────────────┘
                                    │
         ┌──────────────┬───────────┼───────────┬──────────────┐
         ▼              ▼           ▼           ▼              ▼
   [趋势延续策略]  [涨停回踩]  [低位放量]  [主升中继]   ... 策略池 (全部已过 OOS+WF)
         └──────────────┴───────────┼───────────┴──────────────┘
                                    │  各策略当日候选 + 打分
                    ┌───────────────▼───────────────┐
                    │  组合汇总 & 仓位分配 (Portfolio)  │  ← 新增
                    │  去重/打分排序/按 regime 权重分仓 │
                    └───────────────┬───────────────┘
                                    │
                    ┌───────────────▼───────────────┐
                    │  买卖点输出 (tdxclaw tqcenter)   │
                    │  send_warn 提示 / send_user_block 写自选 │
                    └────────────────────────────────┘
```

### 2.1 市场状态分类器(核心改造点)

把 `market_regime.py` 现有的状态量,从"通过/不通过"改为"分类 + 强度打分"。初版建议**只分三态**,越简单越不容易过拟合:

| 状态 | 直觉定义(用现有已算出的量) | 该状态下的策略取向 |
|---|---|---|
| **牛市 / 进攻** | 上涨家数比高、站上 MA5 比例高、首板数明显高于均值 | 放开进攻型策略(首板延续、低位放量),仓位上限高 |
| **震荡 / 中性** | 各项居中,首板数接近均值 | 只留高胜率/低回撤策略(回踩收复类),仓位收紧 |
| **熊市 / 防御** | 跌幅>5% 家数多、跌停多、站上 MA5 比例低 | 大幅降仓甚至空仓,只保留最稳的一两个策略 |

**关键纪律:** 状态阈值本身也是参数,**同样必须进 walk-forward 验证**,不能在全样本上手调到"看起来分得很准"。分类器的输出先只用于"开关 + 仓位系数",不要一上来就做复杂的连续权重函数。

### 2.2 策略路由器(新增,轻量)

一张"状态 → 策略配置"的映射表(建议就用一个 YAML,例如 `strategies/portfolio/regime_router.yml`),内容形如:

```yaml
regimes:
  bull:
    strategies: [first_limit_up_trend_continuation, low_position_volume_breakout]
    max_total_position_pct: 100
  range:
    strategies: [limit_up_pullback_ma5_reclaim]
    max_total_position_pct: 50
  bear:
    strategies: [limit_up_pullback_ma5_reclaim]
    max_total_position_pct: 20
```

路由器只做一件事:根据当日 regime,决定"今天用哪些策略、总仓位天花板多少"。**它不重新发明选股逻辑**,只是调度已入池的策略。

### 2.3 组合回测层(新增,复用 strategy_matrix 骨架)

现有回测是"单策略"维度。组合层要能回答:**把路由器接上后,整条流水线(分类→路由→选股→分仓→买卖)在历史上的年化、最大回撤、盈亏比是多少**,并且这个组合结果本身也要过 walk-forward。这是唯一能回答你"不管牛熊稳定盈利"的检验。

## 3. 严格验证闸门:一个策略怎样才算"入池"

这是你选的强制标准,落成一个不可跳过的检查清单。**任何策略(含从 user 迁移来的、含优化/进化/发现产出的),必须依次通过以下全部关卡,才能进策略池:**

```
关卡 1  基础回测跑通           quant run backtest-strategy <s> --start ... --end ...
        → 验证: 能出结果,指标非退化(胜率>随机,盈亏比>1)

关卡 2  切分验证 (split)        quant validate <s> --mode split
        → 验证: 训练/验证/测试三段表现不塌方,测试段仍为正期望

关卡 3  walk-forward           quant validate <s> --mode walk-forward
        → 验证: 多个滚动窗口下,正收益窗口占比达标、无单窗口主导

关卡 4  参数扰动 (perturbation) quant validate <s> --mode perturbation --max-perturbations 20
        → 验证: 参数±扰动后指标不崩 → 说明不是骑在某个尖峰上过拟合

关卡 5  跨 regime 检查 (新增)   分别在 bull/range/bear 历史区间统计
        → 验证: 明确它"在哪种行情有效",这决定它在路由器里的归属
```

**通过 = 入池,并在池登记表里记录:适用 regime、样本外指标、参数敏感度。** 没过的策略可以继续留在 `user` 做实盘观察,但不进入组合决策。

> 量化门槛(建议初值,后续用数据校准,不要拍脑袋固定):测试段年化为正;walk-forward 正收益窗口 ≥ 60%;参数扰动后最大回撤恶化 ≤ 30%;盈亏比 ≥ 1.5。这些阈值本身要在实施阶段用现有策略的真实分布来定,避免拍出一个谁也过不了或谁都能过的线。

## 4. 分阶段路线图

每个阶段都有明确的"完成 = 可验证"标准,避免"做到能跑就算完"。

### 阶段 A —— 把实战策略正式入池(1 个里程碑,先跑通闭环)
1. 选 **FLUTC** 作为第一个迁移对象(结构最匹配)→ 翻译成 quant 策略 YAML
   - 验证:`quant run select` 当日选股结果,与 user 侧实盘脚本选出的股票高度一致(核对迁移无偏差)
2. 让 FLUTC 走完 §3 的关卡 1–5
   - 验证:产出一份该策略的验证报告(样本外指标 + 适用 regime)
3. 用同样流程处理 LUPB5(quant 已有同名 YAML,做对照)
   - 验证:至少 2 个策略正式入池,登记表建立

**阶段 A 完成标准:策略池里有 ≥2 个"带样本外证据"的策略,迁移-验证这条流水线本身被跑通一次。**

### 阶段 B —— 市场状态分类器
1. 把 `market_regime.py` 从布尔过滤扩成三态分类器 `classify() → {bull/range/bear, strength}`
2. 分类阈值走 walk-forward(§2.1 纪律)
   - 验证:回看历史,分类结果与"事后看真实的牛/震/熊区间"大致吻合,且阈值扰动后分类不乱跳

**阶段 B 完成标准:能对任意历史交易日输出稳定的 regime 标签,且该标签经过样本外检验。**

### 阶段 C —— 路由器 + 组合回测
1. 写 `regime_router.yml`(§2.2)
2. 组合回测层(§2.3),复用 `strategy_matrix.py` 骨架,把"分类→路由→选股→分仓"串成一条可回测流水线
   - 验证:组合的整体年化/最大回撤/盈亏比,且**组合结果本身过 walk-forward**;对比"单策略 always-on"要能看出回撤被压下来了

**阶段 C 完成标准:能回答"这套组合在 2022–2026 历史上,分年度/分 regime 的收益与回撤",并且样本外仍成立。**

### 阶段 D —— 接实时买卖点(落地到 tdxclaw)
1. 每日收盘后跑组合流水线 → 次日候选 + 仓位建议
2. 通过 tdxclaw `tqcenter`:`send_user_block` 写入自选板块(如 `QPOOL`/`QBUY`),`send_warn` 推买卖点提示(双击可下单)
   - 验证:实时选出的股票与离线回测口径一致(避免"回测用的字段实盘拿不到"这类 v7.73 已知限制踩坑)
3. 盘中监控卖点(止损/止盈/移动止盈),复用 user 侧 monitor 思路
   - 验证:纸面跟踪 1–2 周,实时信号与回测假设不背离

**阶段 D 完成标准:每天能自动产出"今日 regime + 启用策略 + 买点股票 + 卖点提示",并推送到通达信。**

### 阶段 E(可选,对应 roadmap 阶段 6)—— 自动调度
把 A–D 固化成定时任务(收盘选股、盘中监控),纳入 roadmap 未完成的"autopilot"。**在 A–D 未经过一段真实纸面验证前,不接自动实盘下单**(与 roadmap 明确列出的 v1 红线一致)。

## 5. 明确的红线(沿用你 roadmap 里已固化的原则)

- 不做任意 SQL 生成、不让 LLM 直接把策略写进生产、不做无边界参数搜索、不自动实盘下单(阶段 E 前)。
