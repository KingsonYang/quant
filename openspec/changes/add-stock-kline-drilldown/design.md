## Context

选股页和回测页目前通过统一接口返回候选与交易字段，前端已有 ECharts 图表能力，但没有股票级日线查询和详情交互。日线数据位于 DuckDB `daily_bar`，股票名称与代码位于 `security_master`。需求同时覆盖两个页面，且 K 线窗口、异常状态和排序规则需要统一。

## Goals / Non-Goals

**Goals:**

- 提供按股票代码和中心日期查询前后约一个月交易日的 OHLC 与成交量数据。
- 在桌面端支持股票名悬停预览，并提供抽屉作为完整查看入口；移动端使用点击/抽屉。
- 选股候选和回测交易复用同一 K 线组件与 API 口径。
- 回测交易明细默认按最新相关日期稳定倒序。

**Non-Goals:**

- 不引入分时数据、实时行情、盘口数据或新的行情供应商。
- 不改变策略信号、回测成交、收益计算和现有交易字段。
- 不在本变更中增加技术指标、画线或交易下单功能。

## Decisions

1. **复用日线数据而非新增存储。** API 从 `daily_bar` 查询复权优先的 OHLC（与现有选股 SQL 一致）和原始成交量，避免数据口径分裂。
2. **以自然月窗口转换为日期范围。** 服务端接收中心日期，计算中心日期前 1 个月至后 1 个月，再返回实际存在的交易日；前端不自行拼接日期，避免节假日和缺失数据问题。
3. **新增独立只读 K 线接口。** 选股和回测页面仅传 `symbol`、`center_date`，接口统一返回股票信息、实际窗口和数据点；无数据、非法代码和数据库异常分别返回可识别错误。
4. **抽屉作为共享详情容器，悬停作为桌面快捷预览。** 悬停预览使用短暂延迟并可取消，点击股票名打开同一抽屉；移动端禁用依赖悬停的行为。
5. **K 线采用双网格图。** 使用现有图表库绘制蜡烛图和成交量柱，时间轴联动、十字光标和 tooltip 展示日期、开高低收、成交量；不引入新的前端图表依赖。
6. **交易排序在前端展示层和接口数据层保持明确。** 回测报告读取后按选股日期、买入日期、卖出日期降序并以代码作为稳定次序；不修改 CSV 生成顺序或回测结果。

## Risks / Trade-offs

- [大量悬停请求] → 增加悬停延迟、按股票和中心日期缓存，并在抽屉打开时复用缓存。
- [复权字段缺失] → 按现有逻辑回退到未复权 OHLC，并在接口元数据标注口径。
- [窗口边界遇到停牌/节假日] → 返回实际交易日并提供 requested_start/requested_end，前端展示实际数据范围。
- [交易日期字段缺失或格式异常] → 使用明确的日期回退链，并保持代码排序作为最终稳定键。

## Migration Plan

先增加查询函数和 API，再增加共享图表组件及两页入口，最后调整交易排序和测试。部署无需数据库迁移；回滚时移除入口和接口即可，不影响历史回测文件。

## Open Questions

- 悬停预览是否需要限制在桌面宽度阈值以上，移动端统一点击抽屉。
- K 线默认是否显示前复权标签及复权字段来源。
- 抽屉是否需要支持从一笔交易跳转到同股票的其他交易记录。
