## Context

参考脚本先用近 250 根日 K 找出近期新高，再对少量候选读取上市以来全历史数据，最终判断信号日最高价是否达到或超过历史最高价。项目已有 DuckDB 全量日线和统一 `pattern_sql` 策略框架，因此无需继续依赖 TdxQuant API，但全历史窗口函数、复权口径和候选排序需要明确。

## Goals / Non-Goals

**Goals:**

- 在任意历史交易日可重复计算历史新高信号，避免使用当前日期造成未来数据泄漏。
- 使用信号日之前的数据计算此前历史高点，允许并列新高。
- 默认限定沪深主板、正常上市、非 ST 股票，并设置最低上市天数。
- 为每日多个候选提供可解释的 `composite_score` 排序，并支持标准策略回测。

**Non-Goals:**

- 不同步通达信自定义板块。
- 不使用盘中实时最高价、集合竞价、盘口或资金流数据。
- 不将“创历史新高”直接解释为买入必然盈利，参数有效性由后续回测验证。

## Decisions

1. **使用前复权价格统一比较。** 信号日与历史日均使用 `COALESCE(high_qfq, high_price)`，避免除权造成伪新高；回退原始价格仅用于缺失复权数据的股票。
2. **严格隔离信号日。** 历史最高价窗口截止信号日前一交易日，条件为 `signal_high >= prior_all_time_high`，防止信号日自身进入历史基准。
3. **保留 250 日预筛语义但由 SQL 优化执行。** 先判断 `signal_high >= prior_250_high`，再对通过者比较此前全历史高点。DuckDB 可由 CTE 和窗口聚合完成，不逐股票调用外部接口。
4. **默认股票池过滤。** 使用 `board`、`list_status`、`name` 和 `list_date` 排除非主板、非正常上市、名称含 ST/退标记及上市时间不足的股票。股票范围与最低上市天数参数化。
5. **排序强调有效突破而不过热。** `composite_score` 由历史高点突破幅度、收盘接近日内高点程度、成交量相对前 5/20 日均量、换手率和近期累计涨幅惩罚组成。历史新高是硬条件，评分只决定同日优先级。
6. **次日开盘执行。** 信号在收盘后确定，回测沿用项目约定在下一交易日开盘买入；默认 1 万元、单仓、Top-1，持有期与止盈止损进入优化空间。

## Risks / Trade-offs

- [全历史扫描成本较高] → 使用 250 日预筛、按日期范围批量查询，并为相关字段建立/利用现有排序结构。
- [前复权序列随分红变化] → 回测和实盘均使用数据库当前统一复权版本，并在结果中注明价格口径。
- [创新高后短期过热] → 通过涨幅、量比、换手和距收盘位置评分及上限参数控制追高风险。
- [ST 名称过滤不完全] → 同时使用板块、上市状态和名称规则，测试常见 `ST`、`*ST`、退市命名。

## Migration Plan

新增参数模型、形态分支、策略 YAML 和测试，不修改现有策略及数据库结构。回滚时删除新策略配置和分支即可。

## Open Questions

- 主板枚举在当前数据中的实际取值需要实施时查询确认。
- 是否默认排除上市不足 250 个交易日的次新股，建议默认排除并参数化。
- 突破幅度上限、量比健康区间和默认持有期需通过多周期回测确定。
