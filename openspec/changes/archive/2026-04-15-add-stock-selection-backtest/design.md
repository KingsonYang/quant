## Context

当前仓库已经具备固定规则选股能力、交易日历能力和日线行情查询能力，但尚未具备一个面向“选股结果质量评估”的最小回测模块。现有 `stock-selection` 更侧重某一个交易日的筛选结果输出，还不能基于同一组选股条件在一段历史交易日区间内重复执行，并把每次入选后的持有期收益整理成统计结果与明细结果。

这次变更的目标不是实现完整交易系统，而是补齐一个轻量、可复现、可解释的“选股成功率回测”能力。它应直接复用现有选股规则和交易日历，不引入资金曲线、仓位、订单、成交、费用和滑点等复杂度。

## Goals / Non-Goals

**Goals:**
- 提供一个基于现有选股规则的历史区间回测入口。
- 支持输入回测时间段、持股周期和选股规则，在区间内逐个交易日执行选股。
- 为每次命中的股票计算单次收益，并输出可读的回测明细。
- 输出面向“选股成功率”的汇总指标和涨跌分布统计，便于快速评估规则有效性。
- 保持结果可重复，确保相同参数下重复执行得到一致结果。

**Non-Goals:**
- 不实现真实交易撮合，不处理开盘买入、次日成交、委托失败等交易细节。
- 不实现资金管理、仓位限制、手续费、印花税、滑点和账户净值曲线。
- 不实现前端页面或图表渲染，第一版只定义可供 CLI 或后续展示层使用的结构化结果。
- 不扩展新的选股规则语法，直接复用现有固定规则与排序参数。

## Decisions

### 1. 将回测定义为“信号效果评估”，不定义为完整交易回测

第一版回测聚焦于回答“某个选股条件在历史上选出的股票，持有 N 天后的表现如何”。因此执行层只做信号回放和收益统计，不落到订单、成交、持仓和权益层。

选择这个方向的原因：
- 现有数据和模块已经足够支撑该能力，投入最小、反馈最快。
- 用户当前关注的是选股成功率，而不是账户资金曲线。
- 可以避免过早承诺交易口径，先把收益计算与统计口径固定下来。

备选方案：
- 直接实现完整交易回测。未采用，因为会同时牵涉订单、成交、费用、T+1 和资金管理，超出这次 change 的最小范围。

### 2. 买卖价格采用“选股日次日开盘价买入，持有 N 个交易日后的收盘价卖出”

第一版统一采用日线级评估口径：
- 买入参考价：选股命中的交易日之后的下一个交易日开盘价
- 卖出参考价：从买入参考日往后推 N 个交易日后的收盘价

选择这个口径的原因：
- 与现有 `daily_bar` 数据天然对齐，不需要引入更细粒度行情。
- 与“收盘后形成信号、次日执行买入”的使用习惯更一致。
- 相比直接用选股日收盘价买入，更接近可执行的实际回测口径。

备选方案：
- 选股日收盘价买入。未采用，因为信号通常在当日收盘后才可确认，直接按当日收盘买入会高估可执行性。

### 3. 回测按交易日历推进，并只在交易日执行选股与持股结束定位

回测区间内的遍历和持股周期计算都以 `trading_calendar` 为准：
- 仅在交易日运行选股
- 持股周期按“交易日数量”计算，而不是自然日
- 卖出日期通过交易日历顺推获得

选择这个方式的原因：
- 与当前项目新增的交易日历能力一致。
- 可避免周末、节假日导致的自然日偏差。

备选方案：
- 直接在 `daily_bar` 中用日期比较。未采用，因为跨证券时日期覆盖不一定完全一致，交易日历更稳定。

### 4. 回测结果拆为“明细结果”和“汇总结果”

第一版输出两层结果：
- 明细结果：每一笔选股命中的证券与对应收益
- 汇总结果：总交易数、已完成交易数、上涨笔数、下跌笔数、胜率、平均收益率，以及按收益区间聚合的涨跌分布

选择这个方式的原因：
- 明细结果便于核查单笔收益和排查口径问题。
- 汇总结果便于快速判断规则是否有效。
- 后续前端或导出可以直接复用这两层结构。

备选方案：
- 只输出汇总。未采用，因为用户已经明确需要类似图片中的历史明细和单次收益。

### 5. 区间末尾无法完成持有周期的记录保留为未完成状态

如果某一笔选股命中的买入日后，不足以找到完整的持有周期卖出日：
- 明细中保留该记录，并标记为未完成
- 汇总统计中的收益、胜率、分布默认只统计已完成记录

选择这个方式的原因：
- 避免静默丢弃尾部样本，让用户知道区间末端仍有未完成持仓。
- 统计口径更清晰，已完成与未完成可分开解释。

备选方案：
- 直接忽略未完成记录。未采用，因为会影响结果透明度。

### 6. 复用现有选股规则结构，不新增自然语言或专用策略 DSL

回测模块直接复用当前 `stock-selection` 的结构化规则输入方式，例如 `rules-json` / `rules-file`、`logic` 和排序参数。

选择这个方式的原因：
- 保持选股与回测入口一致，减少用户重复学习。
- 有利于把“某天选股”和“区间回测”收敛到同一套规则模型。

备选方案：
- 为回测单独设计策略脚本格式。未采用，因为当前阶段没有必要。

## Risks / Trade-offs

- [收益口径与用户认知不一致] → 在 spec、CLI 帮助和文档中明确“次日开盘买入、持有 N 个交易日后收盘卖出”的口径。
- [买入参考日可能超出回测区间末尾] → 对区间末尾无法找到次一交易日开盘价的记录标记为未完成，不纳入已完成收益统计。
- [区间末尾未完成样本影响统计解释] → 在汇总中单独输出未完成笔数，并只对已完成笔数计算胜率和平均收益。
- [大量回测日期重复执行选股查询导致性能下降] → 第一版优先保证正确性；后续如有需要，再通过批量查询或缓存优化。
- [排序参数在区间回测中的语义可能引发歧义] → 第一版允许保留排序参数，但明确定义为“每日选股结果的内部排序”，不影响收益计算逻辑。
