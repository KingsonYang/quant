## Context

当前项目已经具备基于结构化选股规则的普通回测能力，可以按交易日生成命中记录并统计信号收益，但缺少“账户如何实际交易”的约束建模。用户希望新增策略回测，使系统能够在初始资金、持仓上限、单日买入数量、仓位比例和止盈止损规则约束下，模拟真实账户的持仓变化和资金曲线，并输出年化收益率与当前账户余额。

该能力与普通回测的核心区别在于：普通回测关注“命中后单笔收益”，策略回测关注“账户如何在多笔机会之间做取舍并滚动使用资金”。设计上需要在复用现有选股与交易日历能力的同时，引入账户状态、持仓状态和交易执行顺序，确保规则可测试且结果可追溯。同时，策略回测必须作为独立入口存在，避免直接改动普通回测入口和行为定义。

## Goals / Non-Goals

**Goals:**
- 定义策略回测的参数模型，覆盖持股上限、单日买入数量、初始资金、仓位控制、止盈阈值和止损阈值。
- 建立账户级回测执行流程，按交易日维护现金、持仓、已实现收益和未实现市值。
- 明确买卖执行口径，包括先卖后买、按 100 股一手买入、受可用资金和仓位上限约束，以及当日买入持仓次日才能卖出。
- 输出可追溯的账户结果，包括交易明细、账户余额、净值变化和年化收益率。
- 保持普通回测和策略回测两个功能点的入口与行为边界清晰，只复用公共能力而不互相改写。
- 保持第一版实现简单清晰，不引入手续费、滑点或复杂撮合模型。

**Non-Goals:**
- 不计算佣金、印花税、过户费或其他交易成本。
- 不支持融资融券、做空、分红送转、复权调整或多市场差异化规则。
- 不引入盘口撮合、成交量冲击或分笔成交模拟，第一版仅使用日线口径的参考价格。
- 不支持多策略组合调仓或权重优化，第一版只支持单一规则驱动的策略回测。

## Decisions

### 1. 将策略回测建模为独立能力和独立入口，而不是修改普通回测入口

策略回测与普通回测虽然共享选股信号来源，但关注点不同。普通回测评估信号效果，策略回测评估账户表现、资金占用和交易约束。将其定义为独立 capability，并提供独立命令入口，可以避免把账户状态、仓位管理和止盈止损逻辑混入普通回测规范或普通回测代码路径。实现层面应抽取可复用的公共能力，而不是在普通回测流程上直接加条件分支。

备选方案：
- 直接修改 `stock-selection-backtest` 入口：优点是入口集中；缺点是会混淆“信号验证”和“账户模拟”两类行为，也会提高普通回测回归风险。
- 新建 `strategy-backtest` 独立入口：优点是边界清晰，后续也更容易继续演进手续费、资金曲线和仓位管理能力。

### 2. 采用“按交易日循环，先卖后买，并遵守当日买入次日才能卖出”的账户执行顺序

每个交易日先检查现有持仓是否触发止盈止损或到达固定持有期限，完成卖出后再评估新的买入机会。这个顺序符合用户“卖出后才能买入新的股票”的要求，也便于让释放出来的现金在同一交易日后续买入阶段复用。对于当日新开仓的持仓，系统需要记录买入交易日，并在卖出阶段排除这些持仓，直到下一个交易日才允许卖出。

备选方案：
- 买卖分离到不同交易日：实现更简单，但无法满足用户提出的资金轮转要求。
- 同时撮合买卖：规则解释空间较大，且不利于测试可重复性。
- 允许当日买入后因止盈止损立即卖出：实现简单，但与用户要求的交易规则不一致。

### 3. 买入数量以“单笔目标仓位”和“整数手数”共同约束

每个可开仓机会的实际买入股数由以下条件共同决定：
- 当前可用现金；
- 当前账户允许投入的最大仓位；
- 单只股票目标仓位；
- A 股最小交易单位 100 股。

系统先基于仓位控制计算单笔最大可投入金额，再用买入参考价换算为可买手数，向下取整到整数手。如果不足一手，则该机会跳过并记录原因。这一设计能够把“是否能买”“能买几手”显式化，避免出现理论上命中、实盘中却无法成交的记录。

备选方案：
- 固定每次买一手：过于僵硬，无法体现资金规模和仓位控制。
- 忽略整手约束按股数计算：不符合 A 股基本交易规则。

### 4. 收益与账户资产按实际成交金额统计

单笔持仓收益率以实际买入金额为分母计算，账户总资产由现金余额加持仓市值组成。已实现收益通过卖出更新现金，未实现收益通过持仓估值反映。这样既能满足用户“计算收益要按照买入的金额来计算”，也能支持最终输出账户余额和年化收益率。

备选方案：
- 沿用普通回测的“信号收益率平均值”：无法反映仓位分配和资金闲置。
- 只统计已实现收益：无法得到回测结束时的真实账户余额与净值。

### 5. 年化收益率以账户净值区间收益折算

第一版年化收益率基于回测起始净值和结束净值计算，并按回测覆盖的交易日区间折算为年化指标。实现上应优先使用交易日历推导有效交易日数量，避免自然日与交易日口径混淆。

备选方案：
- 只输出累计收益率：信息不足，无法直观比较不同区间策略表现。
- 基于逐日收益序列计算更复杂指标：超出第一版范围。

## Risks / Trade-offs

- [风险] 止盈止损基于日线参考价而非盘中撮合，无法完全还原真实成交时点 -> 缓解：在规范中明确第一版使用日线口径，并把价格口径固定为可测试的参考字段。
- [风险] 用户口头描述中把“当日买入不能当日卖出”称为 T+0，存在术语歧义 -> 缓解：在规范中直接写明行为规则为“当日买入的持仓只能次日及以后卖出”，避免依赖术语简称。
- [风险] “仓位控制”存在多种解释，例如按账户总资产比例还是按可用现金比例 -> 缓解：在 spec 中明确第一版按账户当前总资产比例限制单笔最大投入金额。
- [风险] 当日命中股票较多时，买入优先级会影响最终结果 -> 缓解：要求使用确定性的选股结果顺序或显式排序结果作为买入顺序，保证回测可重复。
- [风险] 回测期末仍有持仓时，账户余额与账户总资产容易混淆 -> 缓解：结果输出同时区分可用现金、持仓市值和账户总资产，并明确“当前账户余额”的定义。
- [风险] 不计算交易成本会高估收益 -> 缓解：在 proposal/spec 中明确这是第一版简化假设，后续可扩展手续费模型。
