## Context

当前仓库已经具备第一版数据模型、DuckDB 逻辑建表 SQL 和初始化数据库脚本，但尚未真正把外部行情数据接入系统。现有数据来源是百度 A 股日 K JSONP 接口，其返回结构包含两部分核心内容：

- `newMarketData.marketData`：以字符串形式承载日线行情，每天一条记录，记录之间用 `;` 分隔，字段之间用 `,` 分隔。
- `reportData`：以日期为键的事件字典，当前样例主要是财报发布类事件。

由于数据源返回的是 JSONP 而不是标准 JSON，且日线行情不是数组对象而是压缩字符串，因此需要在采集链路中显式区分：请求、原始响应、JSONP 解包、结构解析、标准化映射、数据库写入。只有把这条链路标准化，后续回测和分析才能真正消费已有表结构。

## Goals / Non-Goals

**Goals:**

- 实现百度 A 股 JSONP 数据的最小可用采集流程。
- 将 JSONP 响应拆解为原始层记录、标准化日线行情记录和事件记录。
- 将标准化结果写入现有 DuckDB 表结构，包括原始请求、原始响应、`daily_bar` 和 `event_record`。
- 提供最小可运行入口，支持针对单只股票执行抓取、解析和入库。
- 保证解析逻辑对缺失值、`--` 占位值和字段数量异常具备基础容错能力。

**Non-Goals:**

- 本次不实现全市场批量抓取、并发调度和限流优化。
- 本次不实现代理池、重试策略矩阵和复杂抓取监控。
- 本次不补充完整证券主数据初始化、交易日历灌库和复权处理。
- 本次不实现回测引擎调用该数据的完整业务流程。

## Decisions

### 1. 采集流程采用“抓取 -> JSONP 解包 -> 标准化 -> 分层写入”四段式

执行流程明确分为四段：

1. 发送 HTTP 请求，记录原始请求元数据
2. 保存原始响应体到 `raw_market_response`
3. 去除 JSONP 回调外壳，解析内部 JSON
4. 将 `marketData` 和 `reportData` 映射为标准层表并写入数据库

这样设计而不是在一个函数内直接抓取并写表，是为了让原始层与标准层职责分明，出错时可以定位是网络问题、JSONP 格式问题还是字段映射问题。

### 2. `marketData` 解析采用“表头键名驱动 + 占位值清洗”策略

样例中字段顺序由 `keys` 给出，因此解析时以 `keys` 为准，将每一行记录拆分后与 `keys` 对齐，避免把字段位置硬编码到业务逻辑中。对于 `--` 等占位值统一映射为空值，再按字段类型转成 `Decimal`、`int`、`date` 等标准类型。

这样设计比固定下标解析更稳健，因为数据源未来若补充指标字段，只要 `keys` 保持同步，解析器更容易兼容扩展。

### 3. 事件数据按“日期 + 多事件”展开写入

`reportData` 是一个以日期为键、值为事件数组的结构，因此解析时将其展开为多条 `event_record` 记录。事件类型首版固定映射为 `financial_report`，同时保留原始载荷文本，便于后续扩展更细粒度的事件分类。

### 4. 首版写入策略优先保证幂等性

由于 `daily_bar` 的逻辑主键是 `(security_id, trade_date)`，首版入库应采用覆盖或 upsert 思路，避免重复抓取同一证券后产生重复日线数据。事件表首版也应根据业务键控制重复，至少保证同一证券、同一日期、同一事件内容不会被无限追加。

### 5. CLI 首版仅支持单证券执行

首版命令行入口仅支持传入单个股票代码执行一次完整链路：抓取、解析、标准化、写库。批量股票池导入放到后续 change 中处理。这样可以先验证数据链路的正确性，再考虑规模化问题。

## Risks / Trade-offs

- [风险] JSONP 格式可能变化，导致简单字符串裁剪失败 → 优先实现带回调函数前后缀校验的解包逻辑，并保留原始响应便于回溯。
- [风险] `marketData` 行内字段若包含缺失值或字段数不一致，会造成映射失败 → 解析时做字段数校验，异常行单独报错或跳过并记录。
- [风险] 当前没有完整证券主数据初始化流程，入库时可能缺少 `security_id` → 首版允许通过 `symbol` 查询已有主数据，缺失时由调用方先准备主数据或在后续 change 中补全。
- [风险] 事件去重规则过于简单可能漏掉真实重复或误判新事件 → 首版保留原始 payload，并把更复杂的事件幂等设计延后。
- [风险] DuckDB 在并发写入上有限制 → 首版目标是单机单任务导入，该限制可接受。

## Migration Plan

1. 在现有 `src/quant` 下新增采集、解析和入库模块。
2. 为 JSONP 解包、行情解析和事件解析增加单元测试。
3. 扩展 CLI，提供单证券抓取并入库命令。
4. 使用样例数据和真实接口返回进行本地验证。
5. 后续再扩展到批量导入、证券主数据初始化和数据修复工具。

## Open Questions

- 首版是否需要在缺少 `security_id` 时自动创建最小证券主数据记录。
- `daily_bar` 和 `event_record` 的 upsert 在 DuckDB 中最终采用 SQL merge、delete+insert 还是临时表覆盖。
- 是否需要在首版就把 `reportData` 里的 `xcxQuery` 结构化拆分为更多字段。
